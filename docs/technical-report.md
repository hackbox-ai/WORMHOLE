# 虫洞 Wormhole：面向复杂攻击链的图谱认知渗透智能体

## 1 引言

真实业务系统中的安全漏洞往往以多阶段、跨边界的链式形态存在。单个注入点可能只是攻击链的入口，后续还需越权访问、凭据提取、横向移动才能触及目标 flag。传统自动化扫描工具依赖规则匹配与已知签名，无法处理未见过的漏洞模式，更不具备跨步骤推理与方向管理能力。通用大语言模型智能体多采用线性对话模式，每一轮交互之间缺乏结构化的知识持久化，在长时间多步骤任务中容易丢失上下文，重复探索已排除路径。

虫洞提出一种基于有向无环图知识图谱的认知架构，将渗透测试过程建模为事实节点与探索意图边的增量构建过程。智能体在每一轮推理中读取当前图谱拓扑，决定下一步探索方向，执行后将结果沉淀为不可变事实节点。配合自适应调度策略与经验复用机制，系统在有限时间预算内展现出对复杂漏洞链的关联分析与持续学习能力。

## 2 技术架构

### 2.1 编排层与认知层分离

虫洞采用三层分离设计。编排层负责多题调度、资源生命周期管理与平台 API 交互，认知层以知识图谱驱动单题内的多轮探索决策，执行层封装大语言模型驱动的自主工具调用。三层之间的接口严格解耦，认知层不感知执行层的具体后端实现，使得同一套推理逻辑可运行于 Docker 容器编排模式与单容器本地子进程模式。

执行层基于 claude code 命令行工具实现自主工具调用。claude code 内置文件读写、命令执行、代码编写等工具原语，在 `--dangerously-skip-permissions` 模式下可无需人工确认执行任意 shell 命令。认知层通过子进程方式驱动 claude code，将每一轮探索的 prompt 与超时参数注入，收集结构化输出后写入知识图谱。

### 2.2 Blackboard 知识图谱

知识图谱持久化于 SQLite 数据库，启用预写式日志模式以支持编排进程写入与监控进程并发只读。图谱包含两类基本元素。

**事实节点** $f_i$ 为不可变的知识单元，携带唯一标识符与自然语言描述文本。侦察发现、漏洞确认、凭据获取、flag 捕获等结论均以事实节点形式沉淀。事实一旦创建永不修改，确保多轮探索中推理历史完整可溯。

**探索意图** $e_j$ 为有向边，记录从一个或多个已有事实出发的探索假设。推理阶段创建意图时，其目标事实槽位为空，表示探索尚未完成。探索阶段执行完毕后，意图关闭并指向产出的事实节点，形成推理链路。

一次完整的探索转移可形式化表述为：给定当前图谱状态 $G_t = (F_t, E_t)$，推理函数 $\pi$ 基于图谱拓扑生成意图集合 $\{e_{t+1}^{(1)}, \dots, e_{t+1}^{(k)}\}$，探索函数 $\rho$ 执行每个意图并产出新事实 $\{f_{t+1}^{(1)}, \dots, f_{t+1}^{(k)}\}$，图谱演化为 $G_{t+1}$。这一过程的关键在于 $\pi$ 与 $\rho$ 的输入输出均以图谱结构而非自由文本传递，使得推理过程可序列化、可中断、可恢复。

### 2.3 检查点驱动的循环控制

认知循环的推进依赖变更检测机制。每轮探索结束后，系统对图谱执行快照，记录事实计数 $|F_t|$、开放意图计数 $|E_{open}|$、提示计数 $|H_t|$ 三个标量。下一轮推理前，对比当前计数与快照值。若三者均未变化，说明上一轮探索未产生任何信息增益，触发假设重置或退出判断。

该机制将"是否继续探索"的决策从启发式规则转变为基于图谱信息论状态比较的确定性判断，避免了 LLM 自我评估的不可靠性。

## 3 核心方法

### 3.1 自适应止损轮转调度

传统渗透测试智能体常采用顺序单题模式，在一道题上消耗全部预算直到解出或超时。这种策略在面对由简单题与困难题混合组成的题集时效率低下：简单题无需长时间探索即可解出，而困难题即使给予充足时间也未必突破，大量预算被浪费在少数卡住题目上。

虫洞的调度器引入两阶段策略。第一阶段以统一时间窗口 $T_{first}$ 对全部题目执行快速遍历，每题限时十分钟。完成遍历后，未解出题目进入重试队列。第二阶段引入全局时间墙 $T_{deadline}$，当重试队列清空但当前时间 $t < T_{deadline}$ 时，调度器将全部未解出题目的已消耗预算归零并重新入队，持续循环。

单题总预算定义为：

$$B(c) = T_{first} \cdot |F_{flags}(c)| \cdot k$$

其中 $|F_{flags}(c)|$ 为题目 $c$ 的 flag 数量，$k$ 为预算系数。多 flag 题目获得更长总预算，因为每个 flag 可能需要独立的探索方向。重试入队条件为：

$$\text{retry}(c) = \begin{cases} \text{True} & \text{if } t < T_{deadline} \wedge n_{attempts}(c) < N_{max} \\ \text{False} & \text{otherwise} \end{cases}$$

该策略的效果在实验中得到了验证。全部 63 题的首次遍历在约 90 分钟内完成，产出约 80% 的 flag。剩余预算通过 wall-clock 重试机制在后续时间内持续投入困难题目。

### 3.2 死胡同标注与方向剪枝

随着探索轮次增加，图谱中会积累大量已排除的攻击方向。若不在后续推理中明确标注这些方向，LLM 可能重复尝试已知无效的路径，浪费 token 与时间预算。

虫洞在图谱导出阶段对每个事实节点执行死胡同分类。分类采用三层优先级判定：

$$DE(f_i) = \begin{cases} \text{False} & \text{if } \exists s \in S^+ : s \subseteq desc(f_i) \\ \text{True} & \text{elif } \exists p \in P^- : p \subseteq desc(f_i) \\ \text{Neutral} & \text{otherwise} \end{cases}$$

其中 $S^+$ 为强正面信号集合，包含不可辩驳的成功标志如 `flag{`、`successfully exploited`、`RCE confirmed` 等。$P^-$ 为强否定短语集合，包含 `ruled out`、`not injectable`、`exhausted all` 等。正面信号优先级高于否定信号，因为一条事实可能同时描述了失败尝试与最终成功。

被标注为死胡同的事实节点在导出的 YAML 快照中以 `dead_end: true` 字段标记，并在文件头部生成总结注释块。LLM 在下一轮推理时优先读取该总结块，主动规避已排除方向。

### 3.3 跨轮次经验复用

当调度器对某道题目执行重试时，系统并非从空白图谱重新开始。重试启动前，经验提取函数从上一轮的图谱数据库中读取全部事实节点，按死胡同分类结果分为已确认发现与已排除死路两组，构造结构化的经验复用文本块注入新一轮的 origin 提示。

形式化地，第 $n$ 轮重试的 origin 提示 $O_n$ 由原始目标描述 $D_c$ 与经验块 $R_{n-1}$ 拼接而成：

$$O_n = D_c \oplus R_{n-1}, \quad R_{n-1} = \text{extract}(G_{n-1})$$

经验块仅包含与地址无关的结论性知识，如"SQL 注入已排除，端点不可达，有效凭据为 admin:password123"，不包含上一轮的具体 IP 地址或容器地址，因为重试时靶场环境可能已重新部署。

该机制使得第 $n$ 次尝试的智能体等效于一个已经完成了 $n-1$ 轮探索的研究员，只需关注未尝试的方向，显著提升重试效率。

### 3.4 多 flag 实时提交与防丢失

部分题目包含多个独立 flag，若等全部 flag 找齐后统一提交，中途因预算耗尽或靶场宕机退出会导致已发现 flag 永久丢失。虫洞设计双路提交机制：实时路径在每个新事实写入图谱后立即提取 flag 模式并异步提交，批量路径在题目结束时对遗漏 flag 执行补提交。

提交状态去重集合 $A$ 的更新时机是防丢失设计的关键。集合 $A$ 在提交请求成功返回后才执行插入操作：

$$A \leftarrow A \cup \{flag\} \quad \text{only after} \quad \text{submit}(flag) = \text{success}$$

若网络异常导致提交失败，flag 不进入集合 $A$，在后续批量提交阶段可被重新提取并重试。这一设计避免了标记已提交但实际未成功提交的数据丢失陷阱。

**失效 flag 感知与靶场环境轮换对抗。** 多阶段靶场的容器会定期重实例化——IP、网段乃至 flag 值本身随实例漂移。这引入一类隐蔽失效：智能体在实例 $A$ 上捕获的 flag，提交时实例已轮换为 $B$，平台对旧值返回拒绝；而跨轮次图谱继承会累积多个实例的 flag 值，若完成判定仅统计图谱中的 flag 字符串数量，重试轮会在零探索轮次的情况下误判"目标已达成"，反复提交整批过期值——表现为"捕获了 flag 却未得分"。为此引入失效集合 $R$ 与跨轮次持久化状态（每题维护 submitted / rejected 双集合的 flagstate 文件）：

$$R \leftarrow R \cup \{flag\} \quad \text{when} \quad \text{submit}(flag).\text{correct} = \text{false}$$

完成判定随之修正为对失效集合作差：

$$\text{complete} \iff \text{is\_completed} \wedge |F_{flags} \setminus R| \geq n_{target}$$

被拒的 flag 几乎总是上一实例的过期值，进入 $R$ 后永不重提；其从有效计数中剔除迫使重试轮重新探索当前实例、读取新值后再提交。集合 $A$ 亦由 flagstate 跨轮次恢复，已提交（含幂等重复确认）的值在后续轮次直接跳过，杜绝跨轮次重复提交。

### 3.5 停滞检测与退出控制

单题认知循环的退出由三重独立机制控制，各自针对不同的浪费模式。

**预算硬墙**将每轮探索超时限制在该题剩余预算内。**Flag 停滞检测**跟踪连续无新 flag 的轮数，容忍度随已发现 flag 数量自适应增长：

$$N_{stagnation}(c) = N_{base} + N_{per\_flag} \cdot |flags(c)|$$

零 flag 题目在 3 轮无进展后退出，而已找到 3 个 flag 的题目容忍度提升至 9 轮。**基础设施宕机检测**监控连续探索事实中的目标不可达信号，连续 4 次报告 `unreachable` 或 `connection refused` 则判定靶场离线提前退出。

## 6 创新与讨论

虫洞的核心贡献在于将渗透测试从离散的工具调用序列提升为结构化的认知过程。

知识图谱持久化使得每一步探索的结论都成为后续推理的基础，而非一次性消费后丢弃。死胡同标注与经验复用机制使得智能体在跨轮次重试中展现出方向收敛行为：每轮重试消除了更多无效搜索空间，探索效率递增。自适应止损调度策略在简单题与困难题之间实现了预算的自适应分配，wall-clock 机制确保时间窗口被充分利用而非提前退出。

单容器托管后端抽象使得同一套认知逻辑无需修改即可运行于本地开发环境与平台沙箱环境，为实际部署提供了工程可行性。题型自适应知识库的索引路由设计将大规模方法论知识组织为按需加载的分层结构，避免单文件过大导致的上下文窗口溢出问题。

上述设计在 TSec Benchmark 测试平台的首轮遍历中取得了 67.6% 的得分率，验证了认知架构与调度策略的有效性。完整时间窗口实验数据将在后续补充。
