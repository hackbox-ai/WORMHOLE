# 2026-11-16 Update and Acceptance

## Function changes

- Skill/MCP authorization uses a stable Agent key to complete the resource-side write interface; prompts and disables operations when read authorization fails. Both built-in and custom Agents support grant and revocation.
- Business modeling uses independent, reentrant leases and does not occupy ordinary task slots; pause, resume and workspace cleanup continue to comply with life cycle mutual exclusion. There is no new global upper limit for modeling, and you need to consider model concurrency and memory when deploying.
- The workspace adds resource statistics, details, classification preview, manual cleanup and history by task. Retain evidence, reports, attachments, usage and shared references; clearing the database body means that the internal space can be reused, and there is no guarantee that the database file will be shrunk immediately. See [Resource Cleanup Instructions](task-resource-cleanup.md).
- Create a persistent report job for newly discovered transactions; provide retry, cancellation, lease recovery, evidence version, quality check and text history. Reporting sessions use only five limited tools to read existing evidence and commit drafts. QA is not a substitute for fact-checking. Tasks enter the overview by default. See [report-jobs-and-overview.md].
- The test method adds cross-step status, identity clues and permission matrix analysis, as well as offline observation correlation, difference, constraint calculation and candidate generation scripts. The tool is not connected to the Internet, and the candidate does not mean that the vulnerability has been verified.
- Built-in Skill Upgradeable WORMHOLE 0.1.0 Released and unmodified file, LF/CRLF compatible; preserves user editing, revocation of authorization and optional extension boundaries, rejects symlinks. Demo environment dedicated routes do not enter the default method.

Retain WORMHOLE branding, first administrator initialization, independent configuration and data directory, Docker Compose deployment method and Pi SDK 1.5.2, without introducing compatibility with old product configurations.

## Database upgrade

New migration:

1.`0080_task_resource_cleanup.sql`: Task resource path, cleanup job, model body cleanup mark and index.
2.`0081_finding_report_jobs.sql`: Report queue, read record, text version and trigger.

The existing migration file retains its original name and content. Report migration only disables old reporter triggers whose content matches the first version default value, and retains user-defined triggers. Existing reports will not be rewritten in batches during upgrade; historical backfilling is an explicit, bounded operation. The setting name of archive recovery is`wormhole.finding_report_restore`, which is the same as SQL.

Back up the database and running volumes before updating, and then rebuild the application according to the reserved volume update process in the README. Upgrading does not require importing old product data.

## Validation boundaries

Full warehouse testing, complete analysis of the extended matrix, complete production image, and Compose new installation/reserved volume upgrade acceptance were not performed in this round. First version upgrade verification covers actual SQL, account and business status retention; no existing deployments or running volumes are modified. Native model testing uses a deterministic local provider and does not verify real model output quality, cost, or load. All states of browser reporting generation/cancellation/version are not handled one by one, and the corresponding queue behavior is covered by API and native session tests.
