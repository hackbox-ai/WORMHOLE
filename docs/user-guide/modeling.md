# Business Modeling

## Initiate and view

Business modeling can be initiated independently, or the test task can provide the target system entry. Select to view runs, drafts and historical deliveries by system; existing results can be used for incremental verification.

Business modeling is presented in an independent module, and test tasks are displayed in a common task list. The test task continues to execute while the modeling background is updated.

## Identity and Delivery

Identity tags are used to distinguish models and usage scenarios. They should use identifiable names and do not fill in cookies, tokens or passwords.

Draft, running process and delivered version are different states. Which model information is used for test tasks should be judged based on published content and task records.

## Failure handling

Check modeling sessions for specific errors and target reachability. When part of the model is unavailable, you can retry it individually, and existing deliveries can still be viewed; do not judge the entire test task as a failure just based on the modeling time.
