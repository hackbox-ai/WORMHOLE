# PoC Knowledge Base

## Search and add

Unify the PoC library to search by product, vulnerability information and template content, view details and matching conditions, and maintain content using the import or new capabilities provided on the page.

Product aliases are used to associate different names to the same product. When adjusting applicable conditions, fill in the form according to the real version and evidence; leave it blank and let it be judged based on the task and conditions. The rule changes take effect on subsequent selections of new tasks.

## Linked with fingerprint and arrangement

Fingerprints and asset information are used to associate candidate PoCs. Candidate materials are used for Planner to select directions and Workers to verify based on actual conditions. Adoption records are used to track usage and cannot be directly regarded as evidence of vulnerabilities.

Execution depends on scope, version, available tools, operational constraints, and planning. Importing more PoCs does not mean that each task will execute the entire library one by one.

## Verification results

Reported vulnerabilities should include real requests, responses, recurrence conditions, and impact evidence. Template descriptions, product hits, and version guesses should be retained as leads and not directly converted to verified findings.
