# Trace and Log

## View model calls

Large model Trace is used to view calls, tokens, errors, and the original text of requests and responses recorded according to configuration. Whether the original text is visible depends on the recording switch and whether historical data is saved.

Page statistics and specific calls are checked against each other. The text description generated by the model cannot replace the usage or tool output returned by the server.

## Troubleshoot model errors

First record the task, session, model configuration and occurrence time, and check the HTTP status and error content. Authentication, quota, model name, parameters, context and network errors are handled separately.

Check the retry, cooling and configuration switching records again. Multiple layers of retries may extend the wait, but will not fix wrong keys or non-existent models.

## Log and delete

Logs are used to supplement scheduling, service, and tool errors. Prioritize using time and task identification positioning. The original request text may contain test credentials, check the content before sharing.

Deleting the call history will permanently remove the selected records and saved original texts, and is performed according to the page confirmation range.
