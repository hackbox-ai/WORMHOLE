# Business candidate selection and verification

## Have identity
Establish A/B permission matrix from object list, details, attachments, export and status operations; focus on tenant filtering only in the list and omit sub-resources, owner/role and other additional fields to enter the update, invitation code/voucher applicable products are inconsistent with final settlement, one-time resource check and write separation.

## No identity
Find the real reachable business entrance, authentication/encryption/binding chain, JS signature and hidden route; reconstruct the correct method/request body/Content-Type. 200 HTML, 405 and 400 for empty JSON do not mean that the backend authentication has been breached.

## Parameter override
List the actual parameters for the interface: in addition to keyword, it also includes status/vote/type/sort, path ID, body nested field, and subject identifier in header/cookie. Select query, authorization, batch assignment or status experiment according to the real type; do not put quotation marks on all parameters.

## Follow up chain
Upload and save/access/process/attribute, verification code and delivery/proof/final session, tool execution and audit/running subject/isolation, external URL and DNS/HTTP/echo/authorization internal canary. Capabilities and impacts are segmented, and public directories, token decoding, sandbox IDs, or version banners are not regarded as high-risk endpoints.

## Delivery
Use real facts to hand over assumptions, existing evidence, minimum next action, budget and stopping conditions; unmeasured columns BLOCKED/DEFERRED. Reports private data/status effects, measured scope, and unproven boundaries without enforcing vulnerability numbers or levels.
