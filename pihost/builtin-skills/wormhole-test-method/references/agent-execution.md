# Agent tool execution and sandbox boundaries

## Prefix
The real conversation protocol can establish a session and has a shell/python execution tool, or the source code has an execution path. Identity port rejection/conversation port acceptance respectively baseline; public chat itself may be expected.

## Method
1. Request to specify the actual tool to perform the only harmless operation/marker, and record the SSE tool-use/result associated with the log; the model "I executed it" does not testify.
2. When there is only text, independent verifiable calculation and execution evidence is required. If the uncertainty is still unconfirmed, the self-verification of the model will not be induced repeatedly.
3. Determine whether to design a sandbox after confirming execution; own A/B session canary files/history, and approve internal test services for item-by-item comparison. Do not read real other people's history, cloud keys or unknown host files.
4. Attachment backend captures URL and converts it to SSRF; role/conversation tool visibility and final gate control are verified separately. Normal interface rejection/conversation tool can use the same approved resource, which is an independent experiment.
5. Separate natural language, tool schema, and final parameter audit from real side effects.

## Criterion
uid/correct hash/own file only proves capability; unintended anonymous permissions, cross-subject or isolation cross-border require separate evidence and do not directly claim host RCE.
