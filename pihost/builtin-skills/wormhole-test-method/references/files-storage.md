# Upload, path, download and object storage

## Complete chain
Normal small file → STS/pre-signed → save/rename → access URL → parse/convert → business ownership; upload, readable, rendering, execution and permissions are verified separately.

## Method
1. Upload the only harmless mark to your own directory, extension/Content-Type/file name one at a time; check the actual download/preview bytes, do not use 200/CDN address for execution.
2. Download/decompress/path parameter preparation canary inside and outside the approved directory, test normalization/relative path/encoding/soft link to only read these files; the path echo is not read.
3. A/B attachments, previews, exports and signature downloads are separately authorized matrices. Signed path/host/method/expiration is only experimental in another approved bucket/object, missing SignedHeaders field is not individually proven.
4. Check the STS application key/prefix/action with the actual policy; if the empty prefix/wildcard expands the scope, use the isolation bucket to verify the minimum read and write across the subject canary. Do not overwrite the operation diagram, delete unknown objects, or enumerate the entire bucket.
5. Each step of pre-signature expiration/replay/multipart is independently verified, and the actual content is reread after the cache is refreshed to avoid CDN artifacts.
6. CSV formulas are only verified using self-owned cells and controlled tables; document/image conversion is based on real sink conversion and analysis specialization.

## Criterion
Uploading your own key, policy echo, accepting suffix, and downloadability are all segmentation capabilities. Corresponding discovery is supported only when the subject/path/processing boundary is crossed; record recovery and cleanup.
