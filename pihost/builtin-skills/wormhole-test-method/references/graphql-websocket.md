# GraphQL and WebSocket

## GraphQL
Locate the real traffic endpoint and build a baseline with __typename/known legitimate business query. Introspection is visible to the schema, not beyond authority. Own A/B objects verify resolver, nested fields, mutations, and batch alias item-by-item authorization one by one. Compare normal/non-existent/anonymous/another authorized subject and check the private canary; subscription authorization and continuous verification are done separately. Small depth/small paging does not create high complexity query pressure.

## WebSocket/Socket.IO
Record legal handshake Cookie/token/Origin/subprotocol/namespace/message schema. 101 only connects, normal own object message → replace B test object → no object exists, check real reading and writing.
The controlled second origin real browser checks whether it carries the identity and reads the private test message/completes the operation; the lack of Origin verification is not enough. After exiting/token expires, the old connection and the new handshake are verified separately, the unknown real channel is not subscribed, and the connection is closed.

## Criterion
Schema/handshake/event name is entry information; cross-subject private data/state is an independent effect, and one message type does not represent all namespaces.
