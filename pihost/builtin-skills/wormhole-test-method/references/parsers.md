# XML, serialization, prototypes and type semantics

## Fingerprint
Identify Java ac ed 00 05/rO0AB, PHP objects, Pickle, XML/XSLT, and JSON deep merging from legal traffic/Content-Type/source code; feature visibility/saving string does not mean interpretation and execution.

## Method
- XXE: Normal XML, no external references, unique controlled entity comparison, proven by real server callback or approved canary reading; no entity expansion/reading of sensitive system files. XSLT network/file/extension functions depend on actual configuration.
- Deserialization: User input to sink, class/dependency version/reachability, isolated environment harmless marker verification; do not throw unknown gadgets to production or push RCE by rO0AB.
- JNDI: Explicit lookup to controlled endpoint, DNS is not code execution, does not return malicious classes.
- Prototype pollution: Isolate session/process verification __proto__/constructor.prototype is deeply merged, and then the marker is read by an object without input; echo does not prove it. Server-side shared state across requests must be isolated and restored, and pollution must be separated from the impact of templates/permission gadgets.
- Type confusion: normal, different types with the same semantics, null/empty/wrong value comparison, check the real authentication/business status, and do not regard weak language comparison itself as a loophole.

## Criterion
source→transform→parser→sink and the actual effect is complete. Parsing errors/presence of dependencies do not replace reachability, and insufficient security verification conditions remain candidates.
