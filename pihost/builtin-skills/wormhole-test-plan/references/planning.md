# Coverage and handover

## Record three types of progress separately

Acquisition: Whether the source is read/indexed. Test: Hypothesis whether the control is designed and actually performed. Conclusion: Whether the evidence supports or refutes the hypothesis. The three do not replace each other; these are method tags, not adding new enumerations to tasks/findings.

Collate coverage from the real facts/intent/findings of the mission exploration graph:

| Method Label | Conditions of Use |
|---|---|
| PENDING | Not yet executed |
| DONE | The comparison and results of this test unit have been recorded; it does not indicate the existence of a vulnerability |
| BLOCKED | Identity, environment, permissions, resources or criteria are missing, please specify the conditions for reopening |
| NOT_APPLICABLE | There is a clear basis that the target does not exist in this face |
| DEFERRED | Unmeasured due to budget or priority, reserve outstanding account |

Node facts should save: coverage objects, assumptions, controls, observations, evidence references, conclusions, tried variables, blocking and reopening conditions. Use the detail of the existing record_fact to carry these fields, and the Planner will summarize them when reading; do not create a competing "total progress library" in each Worker workspace. Workspace files are only available as attachments or drafts, not as a source of completion status.

## Example of executable intent

"Verify the document reading isolation of authorized test tenant A/B: use their respective objects as baselines, replace only the object ID, and compare the random absence of IDs; use the returned object ownership and data as the criterion, with a maximum of three sets of requests. If there is no evidence, negative cases or gaps will be recorded, and no deletion will be done."

## Deduplication and steering

Compare by target asset + business object + test identity + operation + mechanism, not just by natural language similarity. Negative examples only deny the tested conditions and cannot declare the entire system to be safe. 429. 400 generated by gateway unified template, SPA fallback, and invalid request body are not used as valid business criteria.

## Budget and Recovery

JS/Interface indexing is subject to a limit of 100 files per batch and 25MiB, subject to host and user budget. The source content is hashed to remove duplication, GET/POST are separated, and the interface key retains the origin and version path; token or query values ​​are not put into the summary key. After recovery, make a new judgment based on pictures and real evidence, and directly assume that it has been covered without relying on the compressed summary of the dialogue.
